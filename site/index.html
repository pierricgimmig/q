q is a local-first work queue for coding and research agents. You capture ideas into an inbox, you decide what is ready, and agents take exactly one task at a time with an atomic claim, a lease, and a token they must present to finish it.

cargo install --git https://github.com/pierricgimmig/q q-cli --locked

Installs the q binary. Requires a stable Rust toolchain (1.88+). No account, no server, no config.

The idea

Agents are good at doing work and bad at deciding which work is theirs. q splits those two jobs with a single, explicit gate.

  1. 1

    Capture

    A bare title is a capture. It lands in inbox, tagged with the repo and project discovered from your current directory. Inbox work is never claimable, so you can dump ideas freely.

    $ q "Benchmark trace encoding variants"
captured #1 [inbox] Benchmark trace encoding variants
  2. 2

    Ready

    A human runs q ready. That is the whole permission boundary: there is no MCP tool for it, and agent tokens on a shared server are refused. Nothing moves until you mean it.

    $ q ready 1
ready #1 [ready] Benchmark trace encoding variants
  3. 3

    Agents claim

    Any idle agent asks for one task. The claim runs in one BEGIN IMMEDIATE transaction, so two agents can never take the same work. They start on a branch, heartbeat, and complete with a summary and artifacts.

    $ q claim --agent codex-02
claimed #1 [claimed] Benchmark trace encoding variants
token: 7c0d…e41a
lease_expires_at: 2026-09-27T05:13:30Z

      What you get

      Small surface, sharp edges. Everything below is one binary and one file.

      • Local-first SQLite

        The queue is a single queue.db in your data directory: WAL mode, foreign keys, no daemon. Back it up with cp.

      • Human gate

        Capture always lands in inbox. Only q ready makes a task claimable, and only a human can run it.

      • Leases and claim tokens

        A claim is atomic and carries a 45-minute lease. Heartbeat to extend it; present the token to start, block, release, or complete. Expired claims are recovered.

      • MCP server

        q mcp speaks JSON-RPC on stdio, so Claude Code, Cursor, and Codex get queue_claim_next, queue_complete, and friends with no network port.

      • q serve

        One HTTP authority for a fleet: point every CLI and MCP client at it with --server. Agent tokens cannot call ready; the server enforces the gate.

      • Features and trees

        Group tasks that span repos under a feature, declare dependencies, and read q tree downward to see what has to finish first.

      • Risk gating

        Tasks carry a risk level. Default claims stop at medium; high and external_action work needs an explicit ceiling and a project flag.

      • Watch it move

        q top redraws counts, the table, and recent changes every two seconds. --json is global for scripts and agents.

      The queue does not launch agents, create worktrees, open pull requests, merge, or deploy. It just remembers who is doing what.
